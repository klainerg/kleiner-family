# שורשי משפחת קליינר

אתר סטטי בעברית, מוכן ל־GitHub Pages. אין צורך בהתקנה או בבנייה.

## עריכת הסיפור

- פרק ראשון נמצא בקובץ `content/chapter-1.txt`.
- פרק שני נמצא בקובץ `content/chapter-2.txt`.

ב־GitHub פותחים את הקובץ, לוחצים על סמל העיפרון, עורכים ולוחצים על **Commit changes** לשמירה. אין צורך לערוך HTML או JavaScript. השורה הראשונה שאינה ריקה היא כותרת הפרק. משאירים שורה ריקה בין פסקאות. שומרים בקידוד UTF-8 אם עורכים במחשב.

## הוספת תמונה

1. פותחים את התיקייה `assets/images` ב־GitHub.
2. בוחרים **Add file → Upload files**, מעלים תמונה ושומרים.
3. פותחים את קובץ הפרק ומחליפים את שורת מציין התמונה.

למשל, במקום:

```
תמונה של האיתור מהאתר
```

כותבים בשורה נפרדת:

```
[[תמונה: shika-medal-1985.jpg | האיתור של שיקה משנת 1985]]
```

השם צריך להתאים בדיוק לשם הקובץ, כולל אותיות גדולות או קטנות. מומלץ שם באנגלית עם מקפים. נתמכים JPG, JPEG, PNG ו־WEBP. אין להוסיף את נתיב התיקייה לתוך הסימון. לחיצה על התמונה מגדילה אותה; כפתור הסגירה או Escape סוגרים אותה. אם הקובץ חסר יופיע מציין מקום ברור. שורה שמתחילה ב־`תמונה של` תישאר מציין מקום במיקום שלה בסיפור.

## הוספת פרק שלישי

יוצרים בתוך `content` קובץ בשם `chapter-3.txt`, עם כותרת בשורה הראשונה ופסקאות אחריה. פותחים את `content/chapters.json` ומשנים את הרשימה ל־:

```json
["chapter-1.txt", "chapter-2.txt", "chapter-3.txt"]
```

שומרים. הפרק נוסף לסיפור ולניווט אוטומטית, ללא שינוי HTML או JavaScript.

## הוספת מידע לשאר המדורים

המדורים מוכנים, עם מצייני מקום בלבד. כל התוכן שלהם נערך בקובץ `content/archive.json`. זה קובץ של רשימות: מוסיפים פריטים בתוך הסוגריים המרובעים. הטקסט `יש למלא` בדוגמאות הוא מציין מקום; יש להחליף אותו במידע שלך. יש לשמור על המרכאות, הפסיקים ושמות השדות. בתוך טקסט כותבים `\n` למעבר שורה ו־`\"` למרכאות.

תמונה ראשית: ממלאים את `hero`:

```json
"hero": {"file": "family.jpg", "caption": "יש למלא"}
```

בן משפחה בתוך `family`:

```json
{"name":"יש למלא", "originalName":"יש למלא", "years":"יש למלא", "relationship":"יש למלא", "photo":"person.jpg", "notes":"יש למלא"}
```

אירוע בתוך `timeline`:

```json
{"year":"יש למלא", "title":"יש למלא", "description":"יש למלא"}
```

תמונה בתוך `photos` (מעלים ל־`assets/images`):

```json
{"file":"family.jpg", "caption":"יש למלא"}
```

## הוספת מסמכים

מעלים PDF או תמונת מסמך לתיקייה `assets/documents`. מוסיפים פריט לרשימת `documents` בקובץ `content/archive.json`:

```json
{"title":"יש למלא", "year":"יש למלא", "source":"יש למלא", "description":"יש למלא", "file":"document.pdf", "transcription":"", "translation":""}
```

אפשר להשתמש גם בשם תמונה במקום PDF. תמלול ותרגום הם שדות אופציונליים. עבור מסמך מצולם בתוך הסיפור עצמו, מעלים את תמונתו ל־`assets/images` ומשתמשים בסימון התמונה הרגיל.

מקור בתוך `sources`:

```json
{"archive":"יש למלא", "collection":"יש למלא", "reference":"יש למלא", "description":"יש למלא", "link":"https://example.org", "notes":"יש למלא"}
```

מידע על המחקר: ממלאים את `research` בטקסט שלך. `\n\n` מפריד בין פסקאות.

## פרסום ב־GitHub Pages

1. מחלצים את קובץ ZIP במחשב.
2. מעלים למאגר GitHub את **תוכן התיקייה** `kleiner-archive` כך ש־`index.html` יהיה ברמה הראשית של המאגר, לצד `styles.css`, `script.js`, `content` ו־`assets`.
3. במאגר פותחים **Settings → Pages**.
4. תחת **Build and deployment** בוחרים **Deploy from a branch**.
5. בוחרים את הענף `main` ואת התיקייה `/(root)` ושומרים.
6. כשהפרסום מסתיים מופיעה כתובת האתר במסך Pages.

לאחר עריכה ושמירה, GitHub Pages מפרסם את הגרסה החדשה. התהליך עשוי לקחת כמה דקות; אפשר לראות התקדמות בלשונית Actions. לאחר מכן מרעננים את האתר. לא צריך לבנות דבר או להתקין npm. כל הנתיבים יחסיים ומתאימים גם לכתובת `username.github.io/repository-name/`.

פתיחה בלחיצה כפולה על `index.html` במחשב אינה טוענת את קובצי התוכן בחלק מהדפדפנים. לקריאה משתמשים בכתובת GitHub Pages. אם מותקן Python, אפשר גם להריץ מתוך תיקיית האתר `python -m http.server 8000` ולפתוח `http://localhost:8000`.
